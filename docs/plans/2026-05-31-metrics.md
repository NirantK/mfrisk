# Metrics — mfrisk

_Date: 2026-05-31_

## Convention (locked)

- **Frequency: month-end NAV.** Resample each NAV series to the last available
  NAV on/before each month-end; compute **monthly simple returns**
  `r_t = NAV_t / NAV_{t-1} - 1`. Monthly matches fund factsheets, reduces daily
  noise, and makes downside deviation stable.
- **MAR (Minimum Acceptable Return) = risk-free rate.** Default **RFR = 6.0%
  annual**, configurable in `config.py`. Monthly MAR = `(1+RFR)**(1/12) - 1`.
- All ratios computed **per window**; annualized for comparability.

## Windows

`3m, 1Y, 3Y, 5Y, 7Y, 10Y, 20Y`, each ending at the latest common NAV date
(`as_of`). A window is computed only if the resolved series covers it with a
minimum point count (e.g. ≥ `ceil(0.9 × expected_months)`); otherwise the metric
row is `null` for that window (UI shows "—"). `3m` is short for monthly stats —
computed but flagged low-confidence (≈3 points); primarily for recency, not
ranking.

Plan resolution per window (see ingestion doc): **Direct-Growth ≤10Y**,
**Regular-Growth >10Y / pre-2013**. `plan_used` stored per row.

## Definitions

Let monthly returns be `r_1..r_n`, monthly MAR `mar`, `k = 12` periods/year.

- **CAGR** = `(NAV_end / NAV_start)**(k/n) - 1`.
- **Annualized return** `R` = `(prod(1+r_t))**(k/n) - 1`.
- **Annualized volatility** = `std(r_t, ddof=1) * sqrt(k)`.
- **Downside deviation** (target = `mar`):
  `DD = sqrt( mean( min(r_t - mar, 0)**2 ) ) * sqrt(k)`.
  (Mean over **all** n periods, not only the negative ones — standard Sortino.)
- **Sortino ratio** = `(R - RFR) / DD`.
- **Sharpe ratio** = `(R - RFR) / annualized_vol` (reported alongside for
  contrast; Sortino is the headline).
- **Max drawdown** = `min_t( NAV_t / running_max(NAV)_t - 1 )` on the (daily)
  underlying series within the window.
- **Ulcer Index (Pain Index)** — on the underlying series within the window:
  `Dd_t = 100 * (NAV_t / running_max(NAV)_t - 1)` (≤ 0),
  `UI = sqrt( mean( Dd_t**2 ) )`. Captures both **depth and duration** of
  drawdowns — the felt pain of holding.
- **Martin ratio (Ulcer Performance Index, UPI)** = `(R - RFR) / UI`. The
  Sortino analogue using Ulcer pain instead of downside deviation.

> Ulcer/max-drawdown use the **daily** NAV inside the window (more faithful to
> real drawdown depth/timing), while return-based ratios (Sortino/Sharpe) use
> **monthly** returns per the chosen convention. Both are stored; the doc records
> the asymmetry deliberately.

## Stored `metric` columns

`fund_id, window, plan_used, as_of, n_months, cagr, ann_return, vol,
downside_dev, sortino, sharpe, max_drawdown, ulcer_index, martin`.

Primary ranking keys exposed in UI: **sortino**, **ulcer_index** (lower =
better), **martin**. Secondary: cagr, max_drawdown, sharpe.

## Edge cases (happy-path)

- **Gaps/holidays**: month-end resample uses last NAV ≤ month-end; if a month
  has no NAV (suspended fund), that month is dropped and `n_months` reflects it.
- **Bonus/segregated/IDCW codes**: excluded upstream (Growth-only canonical).
- **Very young funds**: only windows they fully cover are populated; the rest
  are `null`. No extrapolation.
- **RFR sensitivity**: RFR is a single config value in v1 (monthly-NAV +
  MAR=RFR). A time-varying T-bill series is a documented future option, not v1.

## Validation

- Unit tests feed synthetic series with closed-form answers: a constant +X%/yr
  series → Sortino → ∞ (DD=0 guarded), UI → 0; a known drawdown shape → exact
  UI and max-drawdown values.
- Cross-check one real fund (SBI Large Cap Direct-Growth, code 119598) 3Y/5Y
  Sortino & Ulcer against an independent notebook calc before trusting the batch.
